# Gate 5A：产品牌组引擎能力差距

> 状态：`locked_not_implemented`
>
> 审计基线：`codex/godot-hotseat-gate4b-r3-visual-slice@74768e2`
>
> 产品设计清单见 [`card-pool.lock.json`](../design/product-decks-v1/card-pool.lock.json)，结构约束见
> [`card-pool.schema.json`](../design/product-decks-v1/card-pool.schema.json)。本文只规划下一 Gate，
> Gate 5A 不修改 C++、C#、Godot、C ABI、schema 1、`ActionKind` 或 legacy v1 wire。

## 1. 状态定义

| 标记 | 含义 |
|---|---|
| `existing` | 当前引擎已有可复用的核心语义；后续仍需用新合成夹具与产品牌补测试，但不应另写第二套机制。 |
| `fix` | 当前已有相近能力，但语义、区域、触发时机或目标范围与锁定设计不一致；必须改现有唯一实现。 |
| `new` | 当前没有可承载产品规则的通用能力；下一 Gate 需要新增数据模型、验证、执行、快照／事件和测试。 |

“现有”不等于产品牌已实现；它只说明下一 Gate 应复用当前引擎路径。每项能力最终都必须从支付预览、合法行动、
命令验证、实际执行、事件、观看者快照和不变量同源验证，不能只在卡牌脚本中打补丁。

## 3. 必须修正的现有能力

| ID | 状态 | 能力 | 差距与完成条件 |
|---|---|---|---|
| CAP-FX-01 | `fix` | 随从／护符混合五格主战场 | 当前单位固定在五格 `Unit`，旧 `Relic` 位于三格 `Tactic`。改为带槽内类型判别的五格主战场；随从与护符统一占位计数，但攻击、进化、守护检查和随从目标只看随从。满五格时同时拒绝新随从与护符。 |
| CAP-FX-02 | `fix` | 护符倒数与离场 | 把倒数实例从策略区迁入混合主战场；仍在抽牌后递减，归零先释放原格再结算。`LO-03` 必须能在被释放的原格生成衍生物；提前破坏 `NT-03` 不触发倒数结束。 |
| CAP-FX-03 | `fix` | 吸血 | 当前防守方反击也会治疗。改为仅主动攻击者按其实际造成伤害治疗；效果伤害、防守反击、被屏障归零的伤害均不治疗。 |
| CAP-FX-04 | `fix` | 关键词授予与持续时间 | 当前主要支持印刷关键词与临时突进。需要统一“印刷／本回合／永久”三种来源和清理时机；永久 +2/+2、永久屏障等必须随实例留场，离场后清除。wire 冻结 bits 不能被重新编号。 |
| CAP-FX-05 | `fix` | 职业进化充能 | 当前 `DeckList` 只有旧死亡／法术条件。替换为职业级策略：曜誓每周期第一次实际修复最后一道裂痕；渊契每周期第一次单次手牌行动新增至少 2 道裂痕。解锁前不充能、不追溯，解锁后每周期最多 1、封顶 4。 |
| CAP-FX-06 | `fix` | 目标系统 | 当前公共目标主要是主战者／随从。扩展为可区分随从、护符、场地及必要的己方／敌方约束；`NT-04` 的二选一、`AP-08` 的己方系列随从和所有可选目标必须在支付前完整验证。 |
| CAP-FX-07 | `fix` | 必杀与屏障边界 | 保留现有核心路径，但冻结为“随从战斗中实际造成正数伤害”才触发必杀；屏障把该次正数伤害改为 0 后立即移除且不叠层，因而不触发必杀或吸血。效果伤害不得触发必杀。 |
| CAP-FX-08 | `fix` | 战备条件与额外代价 | 当前条件词表只覆盖少量数量／本回合法术条件。扩展为同源谓词：本回合修复、获得屏障、新增裂痕、当前裂痕／生命、历史归零次数、护符倒数离场、控制系列永久物；其中 `LO-S03` 读取“本局至少一次曜誓护符倒数归零离场”，`AP-S03` 只读取“本回合渊契护符因倒数归零被破坏”，不能把前者的永久历史标记误用于后者。`AP-S04` 还要在提交前验证并封存一个合法系列随从／护符。 |
| CAP-FX-09 | `fix` | 离场原因与触发 | 当前死亡／墓地／封存路径不足以表达“破坏”“倒数归零”“场地替换”“部署代价”。所有移动必须携带明确原因；护符倒数归零先离场、同时记为因倒数归零而被破坏，再结算倒数结束；普通提前破坏不伪造倒数结束，场地替换不算破坏，封存不触发遗言。 |
| CAP-FX-10 | `fix` | 遗言与同时离场 | `AP-01` 的负契遗言要在所有死亡实例离场后按既有批次结算，并在结算时读取裂痕；作为部署代价被封存时不得触发。终局发生后不继续抽牌或改变状态。 |

## 5. 逐卡能力追踪原则

机器清单中的每张卡必须把每个效果标成 `existing`、`fix` 或 `new`，并映射到上表的能力类别；机器清单使用更细粒度的
`capability_id`（例如 `repair_cracks`、`repair_to_zero_trigger`），不要求与文档中的聚合编号 `CAP-EX-*`／`CAP-FX-*`／`CAP-NEW-*`
一一同名。下一 Gate 的完成定义是：

1. 每个卡牌效果所引用的能力均已实现且有正向、失败无副作用、响应／终局边界测试；
2. 同一种能力只存在一条验证和执行路径；
3. 合法行动枚举出的每个选择能在同 revision 副本提交成功；
4. 支付预览与实际支付一致，条件在支付及燃耗之后读取；
5. 观看者快照与事件不会通过检索、手牌置底、弃牌或隐藏伏策泄露身份；
6. 规则数字与产品文本来自清单，不散落为 UI 或卡名特判。

## 6. 旧 `midrange`／`advance` 的强制迁移与删除

下一 Gate 不得为了保住旧测试而把旧产品牌组藏在测试开关、未展示菜单或备用 catalog。顺序锁定如下：

1. **盘点依赖**：列出 native、managed、Godot smoke、压力代理、协议 golden 和文档中对旧牌组键、旧 `CardId`、旧中文名及旧卡图的引用。
2. **先抽取合成夹具**：把规则单测需要的最小卡牌写入独立测试 fixture，例如“1PP 1/1”“带守护单位”“固定伤害法术”“响应伏策”；
   fixture 使用测试命名空间和测试专用定义，不使用 `midrange`／`advance` 键，也不伪装成可构筑产品牌。
3. **协议独立**：legacy v1 wire golden 改由协议 fixture 构造冻结字段／字节，不从旧产品牌组开局取得实例。wire 字节保持不变。
4. **迁移自动代理**：压力与整局代理切到誓卫／契术；在新牌尚未完整时可使用明确的 synthetic smoke deck，但不能复用旧产品定义。
5. **接入新产品牌**：完成 34 种可构筑定义、1 个衍生物、两副固定牌和 8 张战备的构筑验证，再迁移菜单与 smoke 配置键。
6. **彻底删除**：删除旧定义、构建函数、数字 ID 常量、牌组键、卡图、视觉目录条目、菜单选项和只为旧卡存在的规则分支。
7. **负向审计**：仓库搜索不得再出现作为运行时产品标识的 `midrange`／`advance` 或旧卡名；历史报告若必须保留文字，须明确标为历史，不得可加载。

不提供旧牌组存档兼容承诺。旧 `midrange`／`advance` 配置在产品切换后应受控报错或由明确的一次性配置迁移转换，
不能静默映射成其中一个新职业。

## 7. 下一 Gate 的建议实现顺序

1. 抽取合成规则／协议夹具，并证明现有覆盖不依赖旧产品卡。
2. 引入标签、混合主战场、独立场地格和离场原因；先建立区域不变量。
3. 引入通用条件事件、模式选择、扩展目标与隐藏信息安全查询。
4. 收紧六关键词，尤其修正吸血，再实现永久修改、衍生物、检索／置底／弃牌。
5. 实现职业充能、永久物监听、历史计数和全部战备条件。
6. 数据化实现并逐卡跑清单契约，随后迁移整局代理和 UI 配置。
7. 删除旧牌组／美术并执行负向审计；最后才进行批量对战数值调优。

任何阶段都不得修改 legacy v1 wire 字节来迁就新内部模型。若客户端 schema 或 C ABI 需要表达新类型，必须另行提出明确版本化计划；
不能在 Gate 5A 的设计文件中假装接口已经支持。

## 8. Gate 5B 落地状态

Gate 5B 已完成不会依赖具体卡名的第一层通用底座：

- `scgs::v2` 的字符串身份、职业／系列／中立标签、五类卡牌、分层关键词和 34＋1 提交态生成目录；
- 随从／护符混合五格、独立场地、显式离场原因、场地非破坏替换、护符原格预留和衍生物召唤；
- 屏障／必杀／主动攻击吸血等基础战斗语义；
- 可暂停选择队列、模式／卡牌／触发排序／额外代价四种选择、选择期间命令阻断、终局清理和当前回合玩家优先的人工排序；
- `scgs_v05` ABI 2.0／schema 2、产品安全 DTO、私密 `PendingChoiceView`、seed 隐藏、纯托管绑定和 Hotseat 选择状态。

本表精确的 9 项修正与 33 项新增能力已经进入生成注册表，并各自由 synthetic fixture 的真实可执行断言覆盖；过滤检索、置底、弃牌、模式、监听器、历史条件、职业充能、战备条件和响应中暂停等通用原语不再只是声明。这里的 42／42 只证明“能力积木”具有规范语义，仍不等于这些积木已经按 34 张牌的规则文本组合成可对战的产品 `Game`。逐卡效果图、跨能力组合、两副固定牌整局和产品代理仍属于 Gate 5C。

## 9. 未完成声明

两副产品牌尚未能在 Godot 产品入口创建、提交或完整对战；v05 foundation adapter 会受控拒绝尚未实现的产品出牌动作。胜率、局长、连动概率和纸面曲线仍未实测，不能因 native／managed／视觉测试通过而写成平衡验收成功。
