# YGOPro / YGOPro2 接入方案

## 上游基线

第一轮客户端基线锁定为：

```text
lllyasviel/YGOProUnity_V2
commit b90f5bbdb0ae60df4060152b94e25a60783040b8
```

该工程使用 Unity 5.6.7，并通过 YGOPro 消息协议驱动对局显示。第一轮不升级 Unity、不替换 NGUI、不改渲染管线。

`Fluorohydride/ygopro-core` 的锁定提交只作为核心 API 和 Lua 系统研究基线。不能默认最新核心与旧 YGOPro2 的原生 DLL 接口逐字兼容；真正替换前必须做 ABI 和协议对照。

## 接入分层

### 第一层：YGOPro2 显示协议

本仓库先保留 210–219 作为 SCGS 私有消息范围：

| ID | 消息 |
|---:|---|
| 210 | 游戏模式 |
| 211 | 玩家状态 |
| 212 | 单位状态 |
| 213 | 进化状态 |
| 214 | 高级召唤状态 |
| 215 | 请求进化方式 |
| 216 | 请求选择素材 |
| 217 | 请求选择印记 |
| 218 | 战术/伏策窗口 |
| 219 | 对局统计 |

该范围位于当前 YGOPro2 核心消息（至 200）与 Sibyl 自定义消息（230 起）之间。接入前仍要在实际分支上全局搜索，确认没有第三方补丁占用。

`client/YGOPro2Overlay` 已提供 Unity 5.6 兼容的解码模型、状态仓库和 `Package.Fuction` / `Package.Data.reader` 适配器。跨语言消息编号、长度和固定字节向量已经由 Python 契约测试检查，但尚未在 Unity 编辑器中编译验证。

应用工具：

```bash
python3 tools/apply_ygo2_overlay.py vendor/YGOProUnity_V2
```

工具会锁定目标提交、检查 210–219 冲突、注入枚举并复制 overlay；它不会擅自重写 `Ocgcore.cs`，因为该文件仍需要结合目标分支的 UI 生命周期人工接线。

### 第二层：把事件映射到 YGOPro2

优先复用已有表现：

- 卡牌移动；
- 抽牌；
- 攻击箭头；
- 伤害与恢复；
- 选择卡牌、位置和选项；
- 召唤与特殊召唤动画；
- 墓地、除外区和额外牌组窗口。

只对 YGOPro 不存在的状态新增消息：PP、当前生命、进化点、进化模式、素材印记、主战者技能和战术窗口。

### 第三层：改造规则核心

不要把原创字段永久塞进游戏王字段：

- `Level` 不等于费用；
- `Defense` 不等于生命；
- `LScale/RScale` 不等于进化点；
- `Overlay` 不等于素材印记。

短期可以复用区域编号：怪兽区→单位区、魔陷区→战术区、除外区→封存区、额外牌组→召唤牌组；但新代码必须用原创语义封装。

## 第一条真实客户端闭环

接入顺序固定为：

1. 在 `Ocgcore.logicalizeMessage` 中把 `p.Fuction` 与未消费的 `p.Data.reader` 交给 `ScgsYgoProPackageAdapter`；
2. 启动原创模式；
3. 显示双方 25 生命与 1/1 PP；
4. 从手牌选择一张白板单位；
5. 核心验证并扣除 PP；
6. YGOPro2 把单位移动到 5 个单位位之一；
7. 结束回合；
8. 对手 PP 增长并抽牌；
9. 两个单位完成一次战斗；
10. 当前生命正确显示且伤害不会回合结束恢复；
11. 生命归零后结束对局。

这条闭环跑通后再接进化、高级召唤和伏策。不要同时改全部 UI。

## 仍未验证的部分

- Unity 5.6.7 在当前构建机上的编辑器编译；
- YGOPro2 原生插件在 Windows x64 的实际加载；
- 210–219 在目标发行分支中是否完全空闲；
- 旧客户端与选定 `ocgcore` 分支的 ABI；
- 网络对局、录像与断线重连；
- NGUI 字体和中文资源打包。

这些项目没有通过就不能宣称“YGOPro2 第一版已经完成”。
