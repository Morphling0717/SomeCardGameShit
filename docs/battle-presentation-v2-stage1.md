# 战斗表现 V2 第一阶段：三张代表卡实机质量关

状态：**独立验收候选，等待用户视觉认可**。本阶段不是全部卡牌／动作改造完成，
也没有将新卡体替换为默认产品画面。编译、规则回归和素材清单通过，不等于
卡片质感、动画节奏或 GPU 最终画面已经通过验收。真实执行结果单独记录在
[第一阶段测试报告](battle-presentation-v2-stage1-test-report.md)。

## 入口与试玩操作

此工作在 `codex/battle-presentation-v2` 上进行，基于已交付的
`codex/product-playable-v1@f060268`；本机 Editor MCP 配置独立保留。
直接正常启动仍进入现有产品菜单。只有显式 `--battle-presentation-review`
才进入候选画面，且不能与 `--ci-product-smoke` 混用。

在包含本实现的 Windows 导出目录中运行：

```powershell
& .\SomeCardGameShit.exe -- --battle-presentation-review
```

源码验收使用锁定 Godot 4.7.2 .NET、SDK 10.0.400 和同源码 `scgs_v05`。
使用项目的 `scripts/dev/start_godot_editor.ps1` 打开唯一编辑器，在该编辑器的
临时运行参数中传入上述用户参数，再经 MCP 运行／观察；无需改变默认主场景。

入口提供三个场面：

| 入口 | 代表卡 | 玩家需要亲手验证的内容 |
| --- | --- | --- |
| 曜誓大团长 · 出牌与进化 | LO-11 曜誓大团长·蕾奥妮 | 卡面、具体格位落牌、卡旁进化、进化异画与人物切入 |
| 禁忌毕业生 · 出牌与进化 | AP-11 禁忌毕业生·诺克缇娅 | 另一职业的同套卡体、出牌、进化异画与人物切入 |
| 界域裁定 · 法术与伤害 | NT-04 界域裁定 | 法术卡面、己方策略位占位、真实目标命中与送墓 |

选择场面后，先显示完全不透明的交接遮挡；**点击揭示后才操作**。
准备器不会替玩家揭示、自动选中代表卡、自动出牌或自动进化。

- 随从：点击手牌来源，再选择一个具体己方空主战场格；也可拖到该格。最后一项
  必要选择完成后自动提交，不再增加一次通用确认。
- 进化：出牌完成后选择场上王牌，通过卡旁动作进入「进化」；按当前合法选项
  完成必要选择，观看进化演出。进化仍由实际能量／次数条件决定。
- 法术：点击「界域裁定」，按当前提示选择伤害模式、己方空策略位和敌方随从。
  **当前控制器先显示模式选择，再选格位／目标**；本阶段不改变既有选择顺序。
  法术必须明确使用一个己方策略位，不能从手牌直接拖到敌方随从来绕过格位。
- 演出中按 **空格**只快进画面，不额外提交命令、不撤销已支付费用。
  此时暂停／结束回合按钮锁定，Esc 不取消已发生的命令。
- 操作状态下 Esc 逐步返回选择；没有选择时打开暂停菜单。「返回验收选择」
  和「重新准备场面」会安全释放旧 session；新场面重新走遮挡与主动揭示。

## 真实规则准备与可追溯证据

`PresentationReviewScenario` 使用现有两副 30 张牌组、真实 session、合法行动查询
与普通 `SubmitCommand` 准备场面，不注入卡牌、不重排牌组、不修改 PP／生命／
进化能量，也不伪造镜头前的规则结果。

准备时强制 Player0 先手、开启洗牌，从显式 seed 范围中寻找代表卡真实在起手的
可达场面。默认最多尝试 64 个 seed、每个最多 96 条合法命令；失败是受控错误，
不会无限准备。两张王牌保留在手中，等待正常回合资源与进化资格；法术场面由
对手实际使用一张随从作为目标。选择／响应通过对应合法命令完成。

准备成功后，session 所有权转交正常热座控制器，从 Covered 开始；两个事件游标
仍为零。准备器是独立的开发验收操作者，不属于玩家实机中的自动代打功能。

每次准备保存新的 `user://review-evidence/*.json`，包括场面、真实配置、合法命令、
逐步 revision、SHA-256 链以及尚未提交的 ready command。Trace 校验检查连续
revision 与哈希链，不能代替对同源码动态库的实际执行验证。

这些文件明确标记为 `development_private_evidence`：可能包含测试 seed、私密
选项 ID 和开发命令，不显示在公共战场、日志或演出队列中，不应打进玩家资源包。
可选 `--review-source-sha=<40位提交SHA>` 仅标明操作者声明的源码版本；默认记录
基线加工作区。两者都不证明工作树干净或 DLL 与该提交一致，最终证据还需记录
实际源码状态、动态库和资产哈希。

## 表现结构与隐私状态机

### 一体化代表卡

仅三张代表卡在验收入口使用 `SculptedCardBody`：同一正面 shader 统一插画、
金属边缘、珐琅名牌、费用／身材镶座和类型纹样，配合独立的真实薄卡边与倒角。
数字及完整卡名仍是 Label3D，不烘焙进插画；卡名只能缩小，不能省略。
手牌、场上及详情视图共用候选布局；其他卡牌仍沿用已发布卡体。

素材复用原有插画和两张王牌进化异画，只新增雕刻材质与两张切入来源图。
切入源文件实际是 **RGB 绿幕图片，不是带透明通道的 PNG**：运行时 CanvasItem
shader 用绿色优势值色键得到透明人物层，并压制边缘溢绿。必须检查最终 GPU
画面是否仍有绿边、缺边或透明度问题，不能以文件名或素材审计冒充透明质量验收。
Cancel／回池会清除切入纹理和身份相关 shader 绑定。

### 公共演出边界

```text
已揭示的合法选择
  → Resolving：清私密 actor／界面，公共投影完整绘制两帧
  → 提交一次 revision 绑定命令
  → Presenting：原操作者方向，输入锁定，仅播放公开事实
  → 同操作者恢复／MulliganReview，或完全不透明 Covered
  → 下一位主动揭示后才能读取其 viewer
```

`ProductHotseatMatchController(session, enablePresentation: true)` 是显式开关；默认
false，旧产品入口行为不变。`State.Presentation` 携带单调 batch ID、前后 revision、
原操作者方向、中立前后战场投影及公共 observation，不携带完整命令、中文日志、
私密快照或手牌。Presenting 时 `Snapshot / Viewer / LegalActions / Events /
PendingEvents` 均为空。提交后只读取此前已揭示的操作者，不能读取下一观看者。

观察数据是 [v05 observation v1 的兼容输出扩展](v05-event-observations-v1.md)：
原生在变更发生点记录端点、格位、真实伤害／治疗、屏障及对象前后状态。
只播放 `version=1 && public_to_all` 的已知事实；不解析旧日志、不按净快照差猜
效果、不重算伤害。已取消攻击不是第二次攻击；攻击声明只表现蓄势，真正命中
必须等待独立的 damage 事实。响应或私密选择暂停时，不提前播放后续结算。

`ProductPresentationDirector.PlayAsync` 不持有 session 或 ACK 能力。当前具备
move、damage、heal、evolve 和 attack declaration 的通用公共反馈；state_change
由中间公共卡面直接更新。每批最多动画化 64 项，超限或玩家跳过时直接收束至
权威 After，而不是丢弃规则效果或无限堆积动画。

临时卡每个 cue 结束回池，进化换图最多同时使用两张替身；能量环、光点、连线和
数值 Label 使用固定池，不逐帧创建 mesh／material。移动、受伤、离场、进化的
中间可见对象按 observation 更新；离场卡不会在回池时被重新显示。

默认候选时长为入场约 480 ms、离场约 280 ms、伤害飞行 240 ms 加命中 340 ms、
攻击声明蓄势约 260 ms、普通进化 1.2 秒、双王牌进化 2.2 秒；减少动画模式压缩
至约 40～50 ms，不播放人物切入或高速飞牌。它们是代码配置，不是体验已获认可。

`CompletePresentation(batch.Id, batch.Revision)` 只允许当前批次完成；旧 ID／revision
或已销毁回调返回 false，不能访问 native。视觉去重水位与两名 viewer 的 ACK
游标独立；演出不提前整批确认尚未展示的私密记录。
Cancel 会使旧等待／回调失效并清敏；它与 Skip 不同，不应触发完成入口。
离场、故障、重开必须先 Cancel，再换屏或销毁 session。

## 实机验收方法与尚未完成项

通过 Godot MCP 打开真实工程、运行入口、主动揭示、点击／拖拽和进化，再读取
实际日志与游戏截图；截图必须是运行游戏，不是编辑器视口。
Director 提供只读 `CiInspectPresentationSafety()`，返回真实 cue 时点、临时卡
绑定／碰撞、切入纹理、可见卡名及费用／身材 Label 的 GPU 矩形和真实底板深度。
V2 的底板证据读取实际一体化正面，而不是已隐藏的旧独立徽章。
`CiCancelPresentationForTest()`、`CiSkipPresentationForTest()` 仅在验收入口可用；
取消探针后应重开该测试 session，不把取消探针当玩家的撤销动作。

`CiInspectPresentationPerformance()` 只读返回验收进程最近 32 批真实播放记录。
它仅采集 Animate 活跃期间连续 `FramePostDraw` 的单调时钟间隔，分别记录首次
workload、重复 workload、真实动画帧／间隔数、p95／最大值、硬件与 VSync／限帧，
以及资源的起点、逐项峰值、同步清理后和两个后续实绘帧。每批最多保存 4,096
个间隔，超限明确标记；不补 idle 帧、不宣称自动完成 600 帧，也不把首次工作负载
当作静态预热。只有很短或跳过的动作可能没有可计算的间隔，此时输出 null。
资源扫描本身的开销包含在下一帧计时中。清理后的宿主可能已经恢复手牌视图，
因此整场材质／纹理数量的变化不能直接认定泄漏；临时卡、碰撞和切入绑定归零
应单独检查。数字预算满足也不能代替完整播放、取消／跳过状态与 GPU 视觉验收。

静态卡面检查与正常速度录像分别取证：终态稳定截图不能证明蓄势、飞行、命中、
换图和落定的节奏正确。四尺寸、GPU 型号／驱动、帧时、资源回收、来源哈希和
Windows/macOS 导出检查的实际结果由测试报告逐项列明；本说明不声称这些已通过。
硬件性能裁决应使用本机实际 GPU，不能把 WARP 软件渲染伪称为硬件验收。

**仍未完成，不在第一阶段完成声明之内：**

- 主战者生命 HUD 在每次伤害／治疗命中时逐条更新；目前部分状态舱仍在批次
  结束恢复快照时刷新。抽牌／调度、伏策链、场地、倒数与所有终局演出的精细整合。
- 对所有动画及最大场面的完整 GPU／600 帧／资源稳定性矩阵、跨平台 shader
  与导出包质量验收；是否实际执行以报告为准。
- 新视觉 golden 的人工批准、最终全量替换与旧产品卡体分支移除。
- 音频、完整 3D 人物、Live2D、自由镜头和主菜单重做；这些不属于本计划首阶段。

必须先交付三场面可操作候选、正常速度录像和卡面近照，**等待用户明确认可
质感与节奏后**再展开第二阶段；自动回归通过或开发者自评不能替代这道质量关。
