# v0.4 行为覆盖清单（Behavior Coverage Checklist）

> 用途：本轮 v0.4 规则重写的**独立验收基线**。每条 = 稳定规则 ID + 行为场景 +
> rules-v0.4.md 章节号 + 对应测试用例名。验收人（用户）对照 v0.4 原文逐条过目，
> 确认后方可合并。机器门槛（测试全绿 + 不变量 + 三种 OS、四个 job 的 CI）之外，本清单是第二道
> 验收线；任一条目无法追溯或测试缺失即验收失败。
>
> 稳定 ID 用于避免章节号漂移：`V04-Rxx` 与规则绑定，章节号仅作引用。

## 逐项场景清单

### V04-R01 PP 容量与补满（§7）
- [x] 容量每回合 +1、无 10 封顶；当前 PP 补满至容量；未用完不保留 → `pp_capacity_growth_and_refill`
- [x] 容量可持续增长至 20 以上 → `pp_capacity_growth_and_refill`

### V04-R02 预支（§9/§10）
- [x] 当前 PP 不足时拒绝普通支付 → `advance_payment_and_limits`
- [x] 预支支付差额：5/5 → 0/2、裂痕 3 → `advance_payment_and_limits`（§9 数字例）
- [x] 每回合只能动用未来一次（预支后燃耗亦被拒） → `advance_payment_and_limits`
- [x] 容量不能降至 0 以下 → `advance_payment_and_limits`
- [x] 当前 PP 足够时请求预支不产生裂痕（§10.2） → `advance_payment_and_limits`

### V04-R03 燃耗（§12/§13）
- [x] 足额支付仍削减容量并产生裂痕（§12） → `burn_cost_and_combined_advance`
- [x] 燃耗占用本回合动用未来 → `burn_cost_and_combined_advance`
- [x] 预支+燃耗组合一次只计一次动用未来（§13） → 覆盖于 `documented_overdraw_walkthrough` 步骤 3

### V04-R04 裂痕（§14）
- [x] 裂痕跨回合保留、自然成长不清除 → `cracks_persistence_and_read`
- [x] 卡牌读取裂痕（裂痕感知者按裂痕数打伤害，封顶 3） → `cracks_persistence_and_read`

### V04-R05 修复（§15）
- [x] 修复 2：移除至多 2 裂痕、容量同步 +2 → `repair_restores_capacity`
- [x] 修复不加当前 PP → `repair_restores_capacity`
- [x] 无裂痕时修复无效（不等于跳费） → `repair_restores_capacity`

### V04-R06 增长（§16）
- [x] 增长设施倒计时结束 → 容量 +1 且无裂痕 → `growth_adds_capacity`

### V04-R07 当前 PP 高于容量（§17）
- [x] 燃耗后 5 当前 / 4 容量为合法状态；剩余 PP 可用 → `current_pp_above_capacity`
- [x] 下回合按新容量补满 → `current_pp_above_capacity`

### V04-R08 超前/按期（§11）
- [x] 超前打出 → OnPlayIfAdvanced 生效（本回合可攻击敌方单位） → `advanced_on_time_status`
- [x] 按期打出 → OnPlayIfNotAdvanced 生效（抽 1） → `advanced_on_time_status`
- [x] 超前打出 → OnPlayIfNotAdvanced 不生效 → `advanced_on_time_status`

### V04-R09 进化与充能（§22/§23）
- [x] 先手第 5 回合解锁 +2 能量、后手第 4 回合 +3 → `evolution_unlock_and_cost`
- [x] 解锁前拒绝、已进化拒绝、消耗 2 点、每回合 1 次 → `evolution_unlock_and_cost`
- [x] 无进化数值的单位默认 +2/+2；有数值的变为进化状态（3/3→5/5） → `evolution_states_and_trigger`
- [x] 进化时触发（抽 1）、获得本回合可攻单位 → `evolution_states_and_trigger`
- [x] 解锁前死亡/施法条件不充能且不追溯；解锁时先手固定 2、后手固定 3 → `charge_requires_evolution_unlock`、`evolution_unlock_and_cost`
- [x] 死亡类充能条件：每回合周期第 2 个己方单位被破坏 +1 → `charge_conditions`
- [x] 法术类充能条件：回合末 ≥2 法术且未打出单位 +1 → `charge_conditions`

### V04-R10 战备部署（§24/§25/§5）
- [x] 条件不满足拒绝（己方 ≥2 单位） → `deployment_flow_and_limits`
- [x] 部署付费、登场、每回合 1 次 → `deployment_flow_and_limits`
- [x] 部署单位被破坏后进入封存区而非墓地 → `deployment_flow_and_limits`
- [x] 指定位置可正是将作为代价封存的组件单位位置 → `deploy_into_archived_donor_slot`

### V04-R11 组件能力（§31）
- [x] 以带组件单位支付部署代价 → 登场单位获得组件（突进）并当回合可攻单位 → `component_grant_and_no_retransfer`
- [x] 支付代价的单位进封存区 → `component_grant_and_no_retransfer`
- [x] 组件离场清除（不变量：场外不得保留授予修饰符） → `component_grant_and_no_retransfer`

### V04-R12 响应栈（§26）
- [x] 攻击宣布开窗；对方伏策取消攻击；攻击者仍视为已攻击；伏策结算进墓地 → `response_stack_lifo`
- [x] 法术使用开窗；无匹配伏策立即结算 → `response_stack_lifo`
- [x] 登场效果准备结算开窗；伏策伤害登场单位；之后按 LIFO 结算原行动 → `trap_entry_pending_damage`
- [x] 反制过牌保留底层响应；反制、响应、原行动严格 LIFO；法术声明伏策可触发 → `spell_response_three_level_lifo_and_counter_pass`
- [x] 响应中目标失效仅跳过依赖效果，同一行动的其他效果继续 → `response_target_invalidation_continues_effects`
- [x] 响应栈层数不变量（≤ 原行动+响应+反制） → `invariants_and_smoke_matches`

### V04-R13 策略区（§5）
- [x] 满格拒绝放置、不自动替换旧卡 → `tactic_zone_no_replacement`
- [x] 伏策每回合至多设置一张、背面朝上 → `trap_set_once_per_turn`
